# COSMY BOS Dashboard Principles

As an Enterprise Business Operating System, dashboards in COSMY are not simply reports—they are **Decision Surfaces**. Every element on a dashboard must drive action or awareness of an actionable state.

## Rule 1: Dashboards are Decision Surfaces
If a metric doesn't drive action, it doesn't belong on the dashboard. Dashboards should not be treated as generic reporting pages.

## Rule 2: Show Exceptions First
Users should immediately see what needs attention before seeing static health metrics.
- **Good**: Overdue Receivables, Compliance Failures, Low Cash Risk, Inventory Issues.
- **Bad**: Top-level Revenue, Expenses, Cash position taking priority over critical alerts.

## Rule 3: The KPI Standard
Every KPI card should answer three questions:
1. **What happened?** (The core metric, e.g., ?12.4M Revenue)
2. **Why?** (The trend or comparison, e.g., +18% vs last month)
3. **What should I do?** (If applicable, an alert state indicating required action)

## Rule 4: Dashboard Freshness
Data confidence is critical. Every widget or dashboard section must indicate its freshness.
- Use Updated: 5 min ago or Live.

## Rule 5: Chart Restrictions
Use space efficiently. 
- **Approved Charts**: Line Chart, Bar Chart, Stacked Bar, Area Chart.
- **Banned Charts**: Pie Charts, Donut Charts, Radar Charts, Gauges, Funnel, Treemap. (These waste space and convey less information).

## Rule 6: Layout & Scrolling
Avoid long vertical scrolling dashboards. Executives should see everything important within one screen or with minimal scrolling. Follow a standardized grid row hierarchy (e.g., Row 1: Alerts, Row 2: KPIs, Row 3: Charts, Row 4: Tables).
